## 6. Bugs (RECORDED, not fixed)

### BUG-1 (confirmed live): duplicate email → HTTP 500 "Erro interno" instead of 4xx — create AND edit
- **Severity**: medium. Wrong status semantics; leaks nothing but breaks the flow with a generic error and no guidance.
- **Repro (create)**: admin → Usuários → Novo usuário → Administrador → fill `Usuário: looptest_dup1`, `E-mail: admin@playmusic.com` (already used by seed admin), `Senha: teste123` → Salvar.
  - Observed: form shows `Erro interno`; POST /api/admin/users → **500**; user NOT created (list unchanged).
- **Repro (edit)**: PUT /api/admin/users/<id> with `email: admin@playmusic.com` on an existing admin → **500** `{"error":"Erro interno"}` (no mutation).
- **Root cause (code-level)**: pg unique violation on `idx_users_email` (0007_user_email.sql) hits `handleStoreError` (helpers.go:78-89), which maps only ErrNotFound/ErrForbidden → falls through to 500 "Erro interno".
- **Expected**: 400/409 with a friendly duplicate-email message (like the other user-facing 4xx).

### OBS-1 (observation, not a regression): no unique index on username
- Migration 0007_user_email.sql adds a partial unique index on email only; username has no unique constraint → duplicate usernames are possible; login-by-username would then return an arbitrary row (store/users.go:81-99 OR-query). Not exploited live (would require a second real-looking account).

### OBS-2 (observation, feature gap): seed admin bootstrap without email
- auth.go:70-75 bootstraps the env-seeded admin without email → until edited, such an admin can't log in by email. In the CURRENT live DB the seed admin has `admin@playmusic.com` (set since bootstrap), so live behavior is fine — gap is only for fresh bootstraps.
